读书笔记 · 微软 ML for Beginners 第六模块（6-NLP）五讲归纳 + 本地实测 NLP TextBlob NLTK VADER 情感分析
一句话掌握全篇
文本 → 分词 / 词频 / 词向量 → 可计算的数字
但「读懂意思」至今仍是难题

五讲从图灵测试一路做到 51 万条酒店评论的情感分析。我最大的收获反而是：NLP 八成的功夫花在数据清洗和「认清数据有多脏」上，模型本身只占两成——光是把 2428 个杂乱标签收敛成 8 个可用字段，就吃掉了整整一讲。

前面几个模块处理的都是数字。这个模块换成人话：文本不能直接喂给模型，得先拆开、数字化，而且「意思」这东西比数值难搞得多——尤其是幽默和讽刺。教材选了个很有意思的载体：先跟《傲慢与偏见》里的伊丽莎白和达西聊天，再拿欧洲 51 万条真实酒店评论做情感分析。

一、NLP 是什么，从哪来

01
NLP 源自计算语言学，目标让机器处理「自然语言」。它已经存在 50 多年，但「真正理解一句话」至今没解决。
计算语言学

研究了几十年：让计算机能处理、理解、翻译、交流语言。偏学术、偏语言学。

NLP

它的工程侧支：让计算机处理人类的口语和书面语。拼写检查、机器翻译、搜索、舆情分析都是它。

真正的难点

不是分词、不是词性，而是理解意思——尤其幽默与讽刺。这一句后面会反复出现。

1.1 三段简史

1950s 图灵测试
人通过打字跟对方对话，如果分不清对面是人还是机器，能说机器在「思考」吗？

灵感来自派对游戏「模仿游戏」：提问者靠纸条提问，判断隔壁房间两人的性别，而对方会故意误导。

1960s ELIZA：第一个「心理治疗师」聊天机器人
MIT 的 Joseph Weizenbaum 开发，能提问、看上去像在听你说话。

它把 I am sad 改写、换时态，回一句 How long have you been sad——只是关键词匹配 + 句式套模板，完全不理解。遇到匹配不上的输入就随机回一句。用户写「你是一辆自行车」，它会回「我当自行车多久了？」。

今天 仍然没解决的那一半
几十年前科幻作家预言人类主要靠说话操作电脑，结果比所有人想象的都难。

「听写转文字」已经很好用了，但理解句子的意思、情绪、讽刺依然是开放问题。

第一讲的作业很有意思：用 6 句随机回复（"That is quite interesting, please tell me more."）写一个叫 Marvin 的机器人。它一个字都不理解，但你会发现——靠随机应答，对话居然能撑好几个回合。这就是图灵测试至今仍有现实意义的原因：「看起来懂」和「真的懂」是两件事。

二、九种常见任务（术语扫盲）

02
任何 NLP 流程基本都是按顺序执行这些任务：先拆开，再标注，再统计，最后才算语义。
任务做什么例子（教材原句）
分词 Tokenization把文本切成 token / 单词要处理标点和不同语言的分隔符，其实不简单
词嵌入 Embeddings把词转成数值向量，语义相近的词在向量空间里挨着'toy' 会和 'disney'、'lego'、'playstation' 聚在一起
词性标注 POS tagging每个 token 标成名词 / 动词 / 形容词fox = 名词，jumped = 动词
句法分析 Parsing识别词与词之间的修饰关系「quick red fox jumped」是一段，「lazy brown dog」是另一段
词频 Frequencies建词典，数每个词 / 短语出现几次Kipling 的诗里 the 出现 6 次，a friend 2 次
N-gram按固定长度切词组：unigram / bigram / trigrambigram 把句子切成 9 个二词组合
名词短语提取找出句子的主语 / 宾语（英文里常跟在 a / an / the 后面）quick red fox、lazy brown dog
词形变化 Inflection取单复数cat ↔ cats
词元还原 Lemmatization还原到词根（lemma）flew / flies / flying → fly
N-gram 的直觉：把它想成一个在句子上滑动的窗口。窗口宽 3，每次右移一格，就得到一个 trigram。它保留了「词序」信息——这是单纯词频做不到的。

另一个必备工具：WordNet。普林斯顿维护的词库，包含同义词、反义词等信息，做翻译、拼写检查都靠它。

2.1 情感分析的两个维度

教材的定义要记牢：

  • polarity（极性）：−1.0 ~ 1.0，越负越负面，越正越正面
  • subjectivity（主观性）：0.0 ~ 1.0，0 = 最客观，1 = 最主观

三、翻译与情感分析：教材第一个跑不通的例子

03
第 3 讲有两个练习：翻译已经彻底跑不通了，情感分析仍然好用。这一节我把两次实测都摊开。

3.1 blob.translate() 已经不存在了

python 
from textblob import TextBlob
blob = TextBlob("It is a truth universally acknowledged, ...")
print(blob.translate(to="fr"))

我在本地（textblob 0.20.1）实测 AttributeError: 'TextBlob' object has no attribute 'translate'。原因不是装漏了依赖——这个模块在包里压根不存在了（包内只有 blob.py、taggers.py、np_extractors.py，没有 translate.py）。而教材自己的 solution notebook 里保存的输出，就是这个一模一样的报错。

降级到旧版也救不回来：translate() 背后调的是 Google 翻译的免费端点，Google 早已封锁，旧版常见报错是 'NoneType' object has no attribute 'group'。加上我这环境 translate.google.com 根本不可达——这个功能在当前条件下是死路，别浪费时间，直接跳过。

教材那句 "you need an internet connection to use blob.translate" 现在得改成：你还需要一个能连 Google 的网络和一个 2019 年的 textblob。

3.2 情感分析：可用，而且结果很有意思

python 
quote1 = "It is a truth universally acknowledged, that a single man in possession of a good fortune, must be in want of a wife."
quote2 = "Darcy, as well as Elizabeth, really loved them; and they were both ever sensible of the warmest gratitude ..."

print(TextBlob(quote1).sentiment)
print(TextBlob(quote2).sentiment)

我本地实测（与教材一致）：

句子polaritysubjectivity解读
开篇名句（quote1）0.2100.271冷嘲热讽：数值上略偏正面，但主观性低 → 像陈述「事实」
结尾大团圆（quote2）0.7000.800明确正面 + 高度主观

教材顺势出了个很有味道的 Challenge：把《傲慢与偏见》全文跑一遍，统计 polarity 恰为 ±1 的「绝对句」谁更多。然后它列了 8 句被判为「绝对正面」的句子让你自己判断——其中三句其实并不正面：

1"Happy shall I be, when his stay at Netherfield is over!"

判为正面。其实是反话——「他走了我才高兴」是在骂人。

2"If I could but see you as happy!"

判为正面。前提是「你要是能开心就好了」= 你现在很惨。

3"Our distress, my dear Lizzy, is very great."

判为正面。great 是正面词，但它修饰的是 distress（痛苦）。

这就是整个模块的核心矛盾：情感分析只认词，不认语境；更认不出讽刺。教材点得很透——简·奥斯汀笔下人物「professing opinions which in fact are not your own」，人类读者能品出来，模型品不出来。

四、51 万条酒店评论：EDA 才是重头戏

04
第 4 讲整讲一个模型都没建，全在做探索性数据分析。它要证明一件事：不把数据摸透就直接上 NLP，得出的结论全是假的。

数据集：515K Hotel Reviews Data in Europe，从 Booking.com 抓的公开数据，覆盖 6 座城市 1493 家酒店，515,738 行 × 17 列（解压后约 230 MB）。

4.1 17 列按用途分成四组

分组字段坑点
酒店Hotel_Name / Hotel_Address / lat / lng地址没用，后面被替换成「城市, 国家」
酒店总评Average_Score / Total_Number_of_Reviews / Additional_Number_of_Scoring三列互相对不上，见下节
评论Reviewer_Score / Negative_Review / Positive_Review / Tags / 字数 / 日期没写内容时填的是字符串 "No Negative"，不是空值
评论者Reviewer_Nationality / 累计评论数评论者没有唯一 ID，无法串联

4.2 三列数字互相对不上

教材拿评论最多的 Britannia International Hotel Canary Wharf 开刀：

口径数值说明
数据集里实际能数出来的评论4789真实可见
Total_Number_of_Reviews 列声称9086差了 4297
再加上 Additional_Number_of_Scoring4789 + 2682 = 7471仍差 1615，补不齐
Average_Score 声称7.1自己算出来是 6.8

于是教材的做法是：别信它，自己算。 加一列 Calc_Average_Score，然后看偏差分布——最大偏差只有 1.3 分（Kube Hotel Ice Bar），绝大多数在 ±1 以内，所以「用自己算的」是安全的。

4.3 没写评论的行，以及一个 50 倍的性能差

情况行数占比
Negative_Review = "No Negative"127,89024.8%
Positive_Review = "No Positive"35,9467.0%
两边都没写1270.02%

有 127 条评论者给了分数、却一个字都没写。教材说这不影响大局，但值得警觉：一份「评论数据集」里居然存在没有评论的行。

更有意思的是教材给的性能对照——统计这些行数，两种写法差了 50 倍：

python 
# 慢：9.64 秒 —— 对 51 万行逐行 apply lambda
no_negative_reviews = df.apply(lambda x: True if x['Negative_Review'] == "No Negative" else False, axis=1)
print(len(no_negative_reviews[no_negative_reviews == True].index))

# 快：0.19 秒 —— 布尔 Series 直接 sum
no_negative_reviews = sum(df.Negative_Review == "No Negative")
这条值得单独记：pandas 里 df.apply(..., axis=1) 是逐行 Python 函数调用，51 万行就是 51 万次函数调用；而 df.Col == "x" 是向量化的 C 层比较。能向量化就别 apply。

4.4 两处必须严肃对待的伦理提醒

① 别把国籍当情绪原因。 教材原话很重：认为「某些国籍的人更爱给差评」是国家或种族刻板印象。每个评论者都是基于自己的经历打分——受过往住店经验、旅途劳顿、个人性格影响。把 nationality 当特征喂进模型，动机很难站得住。（这正是第 1 单元公平性里 over/under-representation 与偏见的老问题。）
② 别自己去读那些差评。 教材特意提醒：公开网站爬来的数据里，有些差评是种族歧视、性别歧视、年龄歧视的。你会看到「天气不好」这种酒店根本控制不了的抱怨，也会看到让人不适的内容。让代码去算情绪，别让人去读。

5.1 Tags：2428 个 → 8 个

Tags 列存的是「文本形式的列表」，顺序不固定、长度 3~6 个不等。硬拆会得到 2428 个不同的标签。教材的做法是先清洗（去方括号和引号），再按出现频次人工筛——判断标准是「这个标签对推荐酒店有没有用」：

保留（有用）次数丢弃（无用）理由
Leisure trip417,778Submitted from a mobile device（307,640）提交设备与酒店无关
Couple252,294Stayed 1/2/3… nights（19 万+）住几晚和满意度关系牵强
Solo traveler108,545Double Room / Superior Double…（各 1~3 万）房型各家酒店都有，无区分度
Business trip82,939房型名称有几十种变体（Classic / Deluxe / Executive…），标准化成本极高，直接放弃
Group（合并 Travellers with friends）67,535
Family with young children61,015
Family with older children26,349
With a pet1,405
python 
df.Tags = df.Tags.str.strip("[']")
df.Tags = df.Tags.str.replace(" ', '", ",", regex=False)

df["Leisure_trip"] = df.Tags.apply(lambda tag: 1 if "Leisure trip" in tag else 0)
df["Couple"]       = df.Tags.apply(lambda tag: 1 if "Couple" in tag else 0)
# ... 共 8 列，命中为 1 否则 0
这一步的方法论比代码重要：不是「把标签都标准化」（教材说很难，因为 Superior Queen Room with Courtyard Garden or City View 根本无从映射），而是退一步问「我要拿它做什么」，然后只保留对目标有用的那几个。这就是 EDA 的价值——先看过数据，才知道能偷多少懒。

5.2 去停用词：395 → 195

停用词是不影响情绪的常用词（the / a / is …）。教材实测：最长的那条差评 395 词 → 195 词，砍掉一半；51 万行两列全部处理只要 3.3 秒，而情感分析要 12~14 分钟，所以这一步很划算。

python 
cache = set(stopwords.words("english"))       # 放进 set，查找 O(1)
def remove_stopwords(review):
    return " ".join([w for w in review.split() if w not in cache])

df.Negative_Review = df.Negative_Review.apply(remove_stopwords)
df.Positive_Review = df.Positive_Review.apply(remove_stopwords)

5.3 VADER 打分

VADER 是基于规则 + 词典的情感分析器（Hutto & Gilbert, 2014），专为社交媒体文本设计。它输出一个 compound 分数，同样在 −1 ~ 1 之间：

python 
from nltk.sentiment.vader import SentimentIntensityAnalyzer
vader_sentiment = SentimentIntensityAnalyzer()

def calc_sentiment(review):
    if review == "No Negative" or review == "No Positive":
        return 0                      # 没写内容就记 0，别让空值污染
    return vader_sentiment.polarity_scores(review)["compound"]

df["Negative_Sentiment"] = df.Negative_Review.apply(calc_sentiment)
df["Positive_Sentiment"] = df.Positive_Review.apply(calc_sentiment)

教材的验证思路很聪明：拿情绪分去跟评论者自己打的分数对撞。如果「差评」文本被判成 +1（极正面）而评分却很低，那要么文本与分数不符，要么分析器错了——而且讽刺是重灾区。教材原话举的例子是 "Of course I LOVED sleeping in a room with no heating"。

我把这句真跑了一遍，VADER 确实翻车：

句子（我本地实测）compound是否判对
The hotel was absolutely wonderful+0.612✅
The heating was broken and the staff were rude−0.727✅
Of course I LOVED sleeping in a room with no heating+0.532❌ 讽刺，被判成正面
这就是 NLP 现在的天花板：字面全是正面词（LOVED），实际意思完全相反。教材说得很实在——你应该预期有一部分情绪分是彻底错的，而且往往能解释得通（讽刺、反语、双重否定）。所以别把情感分当成事实，它只是一个有噪声的特征。

六、我踩到的坑

坑 1 NLTK 数据不会随 pip 一起装

第 2 讲用 ConllExtractor 提名词短语，直接报 Resource 'punkt_tab' not found。它要 punkt_tab（分句）+ conll2000（训练分块器）两个包。装上后 TextBlob('...', np_extractor=ConllExtractor()).noun_phrases 才正常。

坑 2 nltk.download() 在我这环境是坏的

先报 refusing a proxied fetch（NLTK 拒绝代理下载），设 NLTK_ALLOW_PROXIED_URLOPEN=1 放行后又报 CERTIFICATE_VERIFY_FAILED（代理做 SSL 中间人）。解法：绕开 downloader，用 curl 从 jsDelivr 的 nltk_data 镜像直接下 zip 解压到 ~/nltk_data。

坑 3 vader_lexicon 必须保持 .zip，不能解压！

我按惯例解压到 ~/nltk_data/sentiment/vader_lexicon/，结果仍然 Resource 'vader_lexicon' not found。翻源码才发现 NLTK 要的是 sentiment/vader_lexicon.zip/vader_lexicon/vader_lexicon.txt——它自己会读 zip 内部。把 zip 原样放进去就好了。

坑 4 textblob.translate() 已被移除

0.20.1 包里根本没有这个模块，加上 Google 端点已封、网络不可达，不要再尝试，直接跳到第 3.2 节的情感分析。

坑 5 数据集不在仓库里

6-NLP/data/ 只有一个 README，Hotel_Reviews.csv（约 230 MB）要自己从 Kaggle 下。第 4、5 讲的所有代码都依赖它，下载前那两讲跑不了。

坑 6 NLTK 3.10 改了包命名

词性标注模型已改名为 averaged_perceptron_tagger_eng，装老名字 averaged_perceptron_tagger 会报 MissingCorpusError。TextBlob 默认的 FastNPExtractor 还需要 brown 语料。

结语

  1. NLP 的瓶颈在「懂意思」，不在「拆得开」。 分词、词性、词频都很成熟；幽默、讽刺、反语至今是开放问题——VADER 把「我可太喜欢没暖气的房间了」判成 +0.532 就是活例子。
  2. 「看起来懂」≠「真的懂」。 1966 年的 ELIZA 靠换时态就能唬人，今天靠随机应答的 Marvin 也还能撑几个回合。图灵测试打的是观感，不是理解。
  3. EDA 比模型重要。 第 4 讲整讲没建模型，却揪出了三列数字互相对不上、24.8% 的差评是空字符串、127 条没有任何评论的行、2428 个无法标准化的标签。直接上模型的结论全是假的。
  4. 官方给的聚合值要先验证再用。 Average_Score 和 Total_Number_of_Reviews 都算不平；教材的处理是「自己算一遍，偏差在 ±1 内就用自己的」。
  5. pandas 能向量化就别 apply。 同一个统计，df.apply(lambda) 耗时 9.64 秒，sum(df.Col == "x") 只要 0.19 秒——50 倍。
  6. 情感分只是有噪声的特征，不是事实。 要跟用户自己打的分数交叉验证；更要警惕把 Reviewer_Nationality 这类字段当情绪归因，那是刻板印象，也踩第 1 单元的公平性红线。
  7. 环境坑比算法坑多。 NLTK 数据包要手动装、nltk.download() 可能被代理拦、vader_lexicon 不能解压、translate() 已失效——这些跟 NLP 本身无关，但会吃掉你一整个下午。
