一句话掌握全篇
没有标签 → 聚类自动分组
但 k、量纲、评估指标都得你自己负责

分类是「告诉你答案，让你学会判断」，聚类是「什么都没告诉你，让你自己把相似的东西堆成堆」。这一模块两讲跑完，我最大的收获反而是：聚类的分数好看，不代表聚得有意义。

前面三个模块都在做有监督学习——数据带着标签，模型照着答案学。这一模块换了个玩法：数据没有标签（或者你故意不用标签），让算法自己去找结构。教材用了一份很有意思的数据：530 首尼日利亚流行歌曲的 Spotify 音频特征，看看能不能自动分出几类「音乐口味」。

一、聚类是什么：和监督学习的分工

01
聚类属于无监督学习：输入没有对应的标准答案，算法按「相似度」把样本归堆，堆内尽量近、堆间尽量远。
聚类 Clustering

自动把相似对象归成组（cluster）。适合数据没标签、或者你想先探索数据结构的场景。

分类 Classification

先有带标签的训练集，学会映射关系再预测新样本。有标签时优先用它，别硬上聚类。

聚类的典型用途

市场细分、异常/欺诈检测、搜索结果分组、医学影像分型；还能用「簇 ID」代替原始记录来保护隐私。

1.1 算法家族：形状决定选择

类型思路代表算法适合的数据形状
层次聚类按样本间的远近一层层合并/分裂Agglomerative、Ward簇有嵌套结构、数量不定
质心聚类先定 k，再找 k 个中心点，样本归到最近的中心K-Means簇大致是「球状」、大小相近
分布聚类假设数据由若干概率分布混合生成，算归属概率Gaussian Mixture可用统计分布描述
密度聚类按点的稠密程度连成片，稀疏区的点算噪声DBSCAN、OPTICS、Mean-shift非平坦几何、簇大小不均、有离群点
网格聚类把空间划成网格单元再合并BIRCH（也常用于大规模+离群点）多维、数据量大
教材里几个容易卡住的黑话：
· flat / non-flat geometry：距离是走直线（欧氏）还是沿曲面（非欧氏）算，决定该用哪类算法。
· inductive / transductive：前者学成通用规则再套用到新数据；后者先把这批数据（含未知样本）一起分组再贴标签，遇到训练集里没有的新类别时，transductive 更稳。
· constrained：人工加「必须同类 / 必须不同类」的约束，相当于给无监督掺一点监督信号。
· density：点扎堆的紧密程度，密度不均的数据用 K-Means 效果通常很差。

二、第一讲：先可视化，再决定要不要聚

02
聚类极大地依赖可视化。在跑算法之前，先画图看看数据到底长什么样——这一步直接决定了后面选什么算法、以及结果可不可信。

教材自己的反问很有意思：「既然是无监督方法，为什么数据里还有标签？」答案是——标签在探索阶段有用，但聚类算法本身不需要它。这正好给了后面一个作弊式的检验手段：聚完再看簇和真实流派对不对得上。

2.2 清洗：两刀砍掉噪声

两张图都显示：三个流派围绕同一个中心形成同心圆，互相严重重叠。教材原话是「determining clusters in this loosely-aligned data will be a challenge」——可视化阶段就已经把结论摆出来了，后面 K-Means 表现平平一点都不意外。

这一讲真正的方法论：聚类不是「丢给算法就完事」。先画箱线图看离群点、画相关性看冗余特征、画散点/KDE 看分布形状，再决定用哪种算法、选哪些列。跳过这一步，后面所有指标都是自欺欺人。

三、第二讲：K-Means 怎么跑，k 怎么定

03
K-Means 是质心聚类的代表：先定 k 个中心，然后「分配 → 更新 → 再分配」循环到稳定。它最大的限制是你得事先告诉它 k 是多少。

3.1 三步迭代（教材版）

① 选中心采样出 k 个初始质心
→
② 分配每个点归到最近质心
→
③ 更新取簇内均值作新质心
→
收敛质心不再移动

②③ 反复循环，直到新旧质心的差异足够小

直觉上可以把结果想成 Voronoi 图：每个质心有自己一块「势力范围」，范围内的点都归它。代码非常短：

python 
from sklearn.preprocessing import LabelEncoder
from sklearn.cluster import KMeans

le = LabelEncoder()
X = df.loc[:, ('artist_top_genre','popularity','danceability',
               'acousticness','loudness','energy')].copy()
y = df['artist_top_genre']
X['artist_top_genre'] = le.fit_transform(X['artist_top_genre'])
y_enc = le.transform(y)

km = KMeans(n_clusters=3, random_state=0)
y_cluster_kmeans = km.fit_predict(X)
我加的一个小改动：教材写 X = df.loc[:, (...)] 然后直接赋值 X['artist_top_genre'] = ...，这会触发 pandas 的 SettingWithCopyWarning（因为 .loc 返回的可能只是视图）。稳妥做法像上面那样加一个 .copy()。

3.2 内部指标：silhouette 与 inertia / WCSS

指标含义怎么看
inertia_ / WCSS每个点到自己簇质心的平方距离之和（簇内平方和）越小越紧凑；只能横向比较，没有绝对标准
silhouette同一簇内的紧密程度 vs 与最近邻簇的分离程度，取值 −1 ~ 1越接近 1 越好；接近 0 说明簇之间重叠
ARI（外部指标）在已知真实标签时，衡量两个划分的一致程度0 = 随机，1 = 完全一致

3.3 肘部法则：实测 WCSS 曲线

python 
wcss = []
for i in range(1, 11):
    kmeans = KMeans(n_clusters=i, init='k-means++', random_state=42)
    kmeans.fit(X)
    wcss.append(kmeans.inertia_)

sns.lineplot(x=range(1, 11), y=wcss, marker='o', color='red')

四、量纲陷阱：本模块最重要的一课

04
K-Means 用欧氏距离。谁的数值范围大，谁就主导距离——不标准化，就等于把聚类交给量纲最大的那一列。

看一下参与聚类的六列各自的取值范围（我实测的）：

特征minmax标准差在距离里的权重
popularity17317.73几乎独裁
loudness−19.36−0.122.40次要
artist_top_genre020.60很小
acousticness0.0010.8710.203很小
energy0.1110.9950.144很小
danceability0.2550.9510.112很小

popularity 的标准差是 danceability 的 158 倍。这意味着欧氏距离几乎只反映 popularity 的差异，其他五个特征≈摆设。于是我做了一次对照实验：

python 
from sklearn.preprocessing import StandardScaler
from sklearn import metrics

Xs = StandardScaler().fit_transform(X)
labels_s = KMeans(n_clusters=3, random_state=0).fit_predict(Xs)

print("未缩放 silhouette:", metrics.silhouette_score(X,  y_cluster_kmeans))   # 0.547
print("缩放后 silhouette:", metrics.silhouette_score(Xs, labels_s))           # 0.192
print("未缩放 ARI:", metrics.adjusted_rand_score(y_enc, y_cluster_kmeans))    # 0.018
print("缩放后 ARI:", metrics.adjusted_rand_score(y_enc, labels_s))            # 0.164
silhouette（内部指标）ARI vs 真实流派（外部指标）结论
未标准化0.547（好看）0.018（≈随机）分数漂亮，但只分出了「人气高/中/低」
标准化后0.192（难看）0.164（有弱信号）簇变松散，却和真实流派更一致
这是本篇最反直觉、也最值钱的一个结果：标准化让 silhouette 从 0.547 掉到 0.192，看起来「变差了」，但它与真实流派的一致性（ARI）反而从 0.018 涨到 0.164。

原因：不缩放时 popularity 一手遮天，算法把歌按人气高低切成三档，切得干净利落 → silhouette 高；可人气跟流派没关系 → ARI ≈ 0（跟随机分组差不多）。高 silhouette 只是「簇分得整齐」，不代表「分得有意义」。

教材在 Challenge 里也给了同样的提示：scale 之后「silhouette 会下降、肘部图的拐点会变平滑」，我这边实测完全吻合（缩放后的 WCSS 曲线：1716 → 1336 → 1148 → 1030 → 969 → 867 → 816 → 773 → 730 → 675，下降明显更平缓）。

五、别用 accuracy 评价聚类（教材这里有个坑）

教材这一段代码，我建议不要照抄：

python 
labels = kmeans.labels_
correct_labels = sum(y == labels)
print("Result: %d out of %d samples were correctly labeled." % (correct_labels, y.size))
print('Accuracy score: {0:0.2f}'.format(correct_labels / float(y.size)))

它的问题在于：聚类的簇编号是任意的。K-Means 输出的 0/1/2 只是「第几个簇」，LabelEncoder 给出的 0/1/2 是「第几个流派」，两者之间没有任何对应关系。直接相减比较，等于假设「簇 0 恰好就是 afro dancehall」——纯属巧合。极端情况下，把簇的编号整体换一下（0↔2），accuracy 会从 0.39 跳到别的值，但聚类结果本身一点没变。

我实测的结果正好演示了这个荒谬：

评价方式未标准化标准化后是否可信
sum(y == labels) / n0.3880.577不可信，受编号排列影响
adjusted_rand_score0.0180.164可信，与编号无关
正确的做法：有真实标签时，用「划分一致性」类指标，它们都对标签重命名免疫——adjusted_rand_score、homogeneity_score、completeness_score、v_measure_score、normalized_mutual_info_score。没有标签时，就老实用 silhouette / inertia / Calinski-Harabasz 这类内部指标，并配合可视化人工检查。

六、我踩到/发现的坑

坑 1 拿 accuracy 评价聚类

簇编号与真实标签编号没有对应关系，sum(y == labels) 的结果毫无意义。要用 ARI / V-measure。

坑 2 忘了标准化，popularity 一家独大

它的标准差是其他列的几十到上百倍，欧氏距离被它垄断，聚类变成「按人气分档」。K-Means 之前先 StandardScaler 基本是默认动作。

坑 3 把 silhouette 当成「聚得好」的证明

它只衡量簇内紧、簇间远，是内部指标。本例未缩放时 0.547 分很高，ARI 却只有 0.018。指标高 ≠ 有意义。

坑 4 数据本身就不适合聚类

三大流派 206 : 61 : 19 严重失衡，KDE 图上完全重叠，特征间几乎无相关（只有 energy~loudness 0.724）。这种情况下换算法也救不回来——教材最后那句「too imbalanced, too little correlated, too much variance」是诚实的总结。

坑 5 把类别列直接编码进特征

artist_top_genre 被 LabelEncoder 编成 0/1/2 后当作连续数值参与距离计算，等于偷偷假设「afropop 到 nigerian pop 的距离 = 1，且介于 dancehall 之间」。合理的做法是用 One-Hot，或者干脆不把它放进 X。

结语

  1. 有标签就用分类，没标签才用聚类。聚类是在「数据没答案」时找结构的探索工具，它的产出是「分组假设」，不是「标准答案」。
  2. 先可视化，再选算法。箱线图看离群点、热力图看冗余、散点/KDE 看形状——数据长什么样决定了 K-Means、DBSCAN、层次聚类该选哪个。
  3. K-Means 前必须标准化。欧氏距离对量纲极度敏感，不缩放就等于让数值范围最大的那一列独自决定分组。
  4. k 用肘部法则 + 轮廓系数一起定。本例 WCSS 拐点在 2~3，轮廓系数 k=2（0.563）还略高于 k=3（0.547），说明「因为有 3 个流派就取 k=3」只是先验，不是数据给出的结论。
  5. 内部指标好看不代表有意义。silhouette 0.547 配 ARI 0.018 就是活生生的反例：簇分得整齐，但分的是人气不是流派。
  6. 评价聚类别用 accuracy。簇编号任意，用 ARI / V-measure 这类对重命名免疫的指标。
