一句话掌握全片
Agent = LLM（大脑）+ Harness（身体与护栏）

Agent 是「会主动干活的人」，Harness 是「保证他靠谱干活的整套外壳机制」——两者缺一不可。

知识点 1：什么是 Agent（智能体）

  • 定义：能自主完成目标的多步执行 AI 系统，而不是「一问一答」的聊天机器人。
  • 类比：LLM 只是「大脑 / 马」，Agent 是大脑 + 身体 + 工具的完整个体，是会主动干活的人。

四大特征

①目标拆解

把大目标拆成可执行的小步骤

②工具调用

搜索、运行代码、读写文件、调 API

③自主循环

执行 → 观察结果 → 修正，直到完成

④记忆反思

基于历史上下文调整策略

知识点 2：什么是 Harness（缰绳 / 马具）

词源

harness 本义是「马具、缰绳」——用来驾驭马、让马按人的意图干活。

定义

包裹在 LLM 外层的整套工程机制，负责让 AI 稳定、可控、安全、不出错地完成多步任务。

H
模型决定 Agent 的「能力上限」，Harness 决定它的「稳定下限」与落地可行性。

知识点 3：为什么需要 Harness：裸 LLM 的四大问题

1输出不可控

AI 经常「不听话」：不按指定格式输出、答非所问、偷懒（AI 比想象中更会偷懒）。

2会跑偏失控

没有约束时可能偏离目标、陷入死循环（一个死循环就能把 Token 烧光）。

3成本爆炸

多轮工具调用使上下文越滚越大，Token 消耗失控，钱包告急。

4安全隐患

无权限控制时，AI 可能改错文件、执行危险命令、访问不该访问的资源。

知识点 4：Harness 的组成：Agent 背后的「隐形操作系统」

①上下文管理

上下文拼装与压缩，防止上下文爆炸，控制成本。

②工具调用循环

承接 Function Calling / MCP，让模型能实际「动手」。

③结构化输出控制

JSON Mode / 输出解析器，强制模型按约定格式返回。

④权限与沙箱

命令白名单、目录范围限制、沙箱隔离，管住「能做什么」。

⑤错误处理重试

格式校验、自动重试、错误回退，发现错误并纠正。

⑥成本控制

Token 预算、轮次限制、超时中断。

⑦记忆管理

短期上下文与长期记忆的读写与过期策略。

⑧日志审计

Log / Trace / 审计记录，可回放、可追溯、可人工介入。

知识点 5：Agent 的运行机制：Agent Loop

ReAct 范式：思考 → 行动 → 观察 →（循环直到完成）

Reasoning思考
→
Acting调用工具行动
→
Observing观察结果
→
目标达成输出 / 终止

执行 → 观察 → 修正，未达成目标则回到「思考」继续循环

  • ReAct（主流）：思考一步、行动一步、观察一步，边想边做。
  • Plan 范式：先整体规划任务清单，再逐步执行，适合复杂长任务。
  • 多 Agent / 子 Agent：主 Agent 派出子 Agent 分工或并行，各管各的上下文与权限。
  • 护栏必备：循环必须配轮次上限 / 预算 / 超时，否则就是「烧钱的无底洞」。

知识点 6：工具调用的两个关键概念（易混淆，重点避坑）

概念说明
Function Calling让模型输出「结构化调用意图 + 参数」的具体实现机制，是底层能力。
MCPModel Context Protocol——统一工具接入的开放协议 / 标准，相当于给 AI 配的「USB 接口」，一次接入处处可用。
易错点：MCP ≠ Function Calling（一个是协议标准层，一个是实现机制）；「调用外部工具 / 服务」≠「调用另一个 AI」。分清这三层，能避免大量争论。

知识点 7：工程范式的演进：Prompt → Context → Harness

2023–2024

Prompt Engineering

核心问题：怎么问

提示词措辞、示例、角色设定。

2025

Context Engineering

核心问题：让 AI 看到什么

上下文文档、相关信息注入。

2026 · 当下

Harness Engineering

核心问题：系统能预防 / 测量 / 修复什么

外层工程机制：校验、约束、重试、预算、审计。

三者是层层叠加而非替代：Prompt 管「怎么说」，Context 管「能看到什么」，Harness 管「系统如何兜底」。Agent 做得好不好，关键看外层 Harness 能否预防错误、测量错误、修复错误。

知识点 8：实战要点：让 Agent 靠谱落地的工程手段

要点做法
防 Token 爆炸限制每轮输出与总轮数、定期压缩上下文、丢弃冗余历史。
防死循环设置最大迭代次数、超时中断、检测「重复动作」即终止。
保输出格式优先使用模型的结构化输出（JSON）模式，程序侧再做解析校验；把固定规则写入 system 字段，比每次临时叮嘱更可靠。
控执行边界权限白名单、沙箱、审计日志，让 AI 只能在授权范围内干活。
反馈闭环用 Lint / 单测 / 校验器等自动化信号及时纠错，错了就拉回来重试。

核心结论速记

  1. Agent = LLM + Harness，缺一不可——只有模型没有外壳，干不成多步实事。
  2. 分工：Agent 负责「聪明决策」，Harness 负责「稳定执行」。
  3. Agent 的可靠程度，不取决于模型有多强，而取决于外层机制能否预防、测量、修复错误。
  4. Harness Engineering 是当下 Agent 从 Demo 走向生产可用的核心命题。
  5. 评判一个 Agent 好不好用就看三点：能否稳定干完活、不捅娄子、成本可控。
