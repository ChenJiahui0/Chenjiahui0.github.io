读书笔记 · 微软 ML for Beginners 第七模块（7-TimeSeries）三讲归纳 时间序列 ARIMA SARIMA SVR MAPE
一句话掌握全篇
历史负荷 → 差分变平稳 → 拟合 / 核映射 → 未来值
铁律：测试集必须晚于训练集

三讲做同一件事——用 GEFCom2014 三年每小时电力负荷预测未来负荷，先上经典的 ARIMA，再上能抓非线性的 SVR。我最大的收获是：时间序列里「怎么切数据」比「选什么模型」更要命——随机切一刀，模型就偷看了未来，准确率全是假的。

前面五个模块的数据基本都是可交换的：打乱行顺序不影响建模。时间序列打破了这个前提——行的顺序本身就是信息。教材把它比作「水晶球」：靠一个变量过去的表现，预测它未来的值。别看它不如深度学习热门，它直接对口定价、库存、供应链，是商业价值最直接的 ML 方向之一。

一、三个定义，别混着用

01
教材刻意把 time series / analysis / forecasting 三个词分开讲，因为它们常被当成一回事。
Time series 时间序列

「按时间顺序排列的一串数据点」，通常是等间隔连续采样。例：道琼斯指数的每日收盘价。

Time series analysis 分析

对这类数据做分析，方法有时域、频域、线性、非线性等。还包括 interrupted time series——看某个打断事件前后规律怎么变。

Time series forecasting 预测

用模型基于过去呈现的规律预测未来值。可以用回归（把时间当 x），但最好用专门模型——最常见的就是 ARIMA。

教材开了个很生活的头：你维护一片智能停车表，能记录每个车位被使用的频率和时长。能不能根据它过去的表现，按供需规律预测未来的收费？高峰期涨价会让找车位的人不爽，但确实是给街道清洁筹钱的办法。

1.1 本次的数据集

用的是 GEFCom2014 预测竞赛的数据：2012–2014 三年、每小时的电力负荷（load）与温度值。任务是「只用历史负荷，往前预测一个时间步」——这就是单变量时间序列（Univariate Time Series），即只有一个随时间变化的变量。

教材还举了 NIST 的经典例子：莫纳罗亚观测站的月度 CO₂ 浓度。1975 年 12 个月从 330.62 一路到 328.41 再回到 330.97——先降后升，这就是季节性。

二、六个要看的数据特征（都是「噪声」）

02
如果你把时间序列当成一条「信号」，那下面这六样东西就是要先识别、再削弱的噪声。
1Trends 趋势

随时间可度量的上升或下降。要会用，必要时也要会去掉。

2Seasonality 季节性

周期性波动，比如节假日对销量的影响。

3Outliers 异常值

远离正常波动范围的点。

4Long-run cycle 长周期

独立于季节性、跨越更久的周期，比如持续一年以上的经济下行。

5Constant variance 恒定方差

随时间保持相似的波动幅度，比如用电量的昼夜起伏。

6Abrupt changes 突变

突然的跃变，需要单独分析。教材举的就是疫情导致企业骤停造成的断点。

怎么看出来？ 教材第一讲唯一的代码就是画图——先画三年全景，再放大画 2014 年 7 月的第一周。放大之后，日内起伏（昼夜）和周内起伏（工作日/周末）才看得清。这一步不能省。

三、ARIMA：把 A-R-I-M-A 拆开

03
= AutoRegressive Integrated Moving Average，自回归积分滑动平均。它特别适合拟合非平稳数据。

3.1 两个前置概念

Stationarity 平稳性

统计上指数据分布不随时间平移而改变。非平稳数据会因为趋势而波动，必须先变换才能分析——季节性带来的波动可以靠「季节性差分」消掉。

Differencing 差分

把非平稳数据变平稳的手段：去掉非常数的趋势。原文定义很精准——「差分移除时间序列水平上的变化，消除趋势和季节性，从而稳定均值」。

3.2 三个字母各自干什么

字母含义在做什么
AR AutoRegressive自回归「回头看」：用过去的值（叫 lags 滞后值）做假设。形式上是「目标变量对它自己滞后值做回归」。例：每月铅笔销量作为演化变量。
I Integrated积分 / 差分ARIMA 区别于 ARMA 的地方：施加差分步骤以消除非平稳性。
MA Moving Average滑动平均输出变量由当前和过去的滞后值共同决定。

3.3 p / d / q 三个参数

教材说得很直白：这三个参数就是用来刻画时间序列的季节性、趋势、噪声三大方面的。

参数对应部分作用
pAR 自回归纳入过去多少个值
dI 积分做几阶差分
qMA 滑动平均纳入多少个过去的预测误差
数据有季节性就用 SARIMA：这时还要多一组 P、D、Q，含义与 p/d/q 对应，但管的是季节性分量，外加一个周期长度。本例是小时数据，日周期就是 24。

四、动手：ARIMA 建模全流程

04
训练 1416 小时、预测未来 3 小时，最后用 walk-forward 前进验证 评估。
① 切分训练 1416 / 测试 48
→
② 缩放MinMaxScaler 到 0~1
→
③ 定阶order + seasonal_order
→
④ 前进验证720 小时滑动窗口
→
⑤ MAPE单步 0.56%

HORIZON = 3，即一次预测未来 3 个小时

4.1 切分：测试集必须晚于训练集

python 
train_start_dt = '2014-11-01 00:00:00'
test_start_dt  = '2014-12-30 00:00:00'

train = energy.copy()[(energy.index >= train_start_dt) & (energy.index < test_start_dt)][['load']]
test  = energy.copy()[energy.index >= test_start_dt][['load']]

# Training data shape:  (1416, 1)
# Test data shape:      (48, 1)
这里是全部三讲最重要的一句话：教材原话——「必须确保测试集覆盖训练集之后的时间段，以保证模型不会从未来时间段获取信息」。这条一旦破坏（比如随机 8:2 切分），MAPE 再漂亮也是自欺欺人。

而且理由很实在：这份数据日消费有强季节性，但与最近几天最像——所以只用一小段时间窗训练就够了（1416 小时 ≈ 59 天）。

4.2 缩放：只用训练集拟合

python 
scaler = MinMaxScaler()
train['load'] = scaler.fit_transform(train)   # 只在训练集上 fit
test['load']  = scaler.transform(test)        # 测试集只做 transform

这个顺序不能反。用测试集 fit 就等于把测试集的取值范围泄漏给了模型——是 4.1 那条铁律在特征工程上的延伸。

4.3 定阶与拟合

python 
from statsmodels.tsa.statespace.sarimax import SARIMAX

order          = (4, 1, 0)        # p=4, d=1, q=0
seasonal_order = (1, 1, 0, 24)    # P=1, D=1, Q=0, 周期 24 小时

model   = SARIMAX(endog=train, order=order, seasonal_order=seasonal_order)
results = model.fit()
选参数这件事本身很痛：教材说它「某种程度上主观且耗时」，并建议考虑 pmdarima 库的 auto_arima() 自动搜参。这跟前几课手调超参的思路一致——有自动搜索就别硬猜。

4.4 前进验证（walk-forward）：黄金标准

思路：从序列开头起，先在训练集上训练，预测下一个时间步；拿预测值和真实值比对；然后把真实值并入训练集，再预测下一步，如此循环。

python 
training_window = 720          # 固定 30 天（720 小时）
order           = (2, 1, 0)    # 注意：这里换成了 2，不是上面的 4
seasonal_order  = (1, 1, 0, 24)

history = [x for x in train_ts][-training_window:]

for t in range(test_ts.shape[0]):
    model     = SARIMAX(endog=history, order=order, seasonal_order=seasonal_order)
    model_fit = model.fit()
    yhat      = model_fit.forecast(steps=HORIZON)
    predictions.append(yhat)

    obs = list(test_ts.iloc[t])
    history.append(obs[0])     # 加入真实值
    history.pop(0)             # 同时从头部丢弃，保持窗口固定
两个易漏的细节：
① 窗口要固定——每加一个新观测，就从开头删一个旧的，否则训练成本会一路涨。
② 代价是算力：这里 48 步就要重训 48 个 SARIMAX 模型。教材明说「数据小或模型简单时可以接受，规模化时可能成问题」。

教材把 walk-forward 称为「时间序列模型评估的黄金标准，推荐在你自己的项目中使用」。

4.5 MAPE 与结果

MAPE 的定义：每一个预测点上，|实际 − 预测| ÷ 实际，取绝对值求和，再除以点的个数 n。教材给的直观读法——MAPE 为 10 就是平均偏了 10%。

python 
eval_df['APE'] = (eval_df['prediction'] - eval_df['actual']).abs() / eval_df['actual']
print(eval_df.groupby('h')['APE'].mean())
口径MAPE含义
单步预测（t+1）0.557%只预测下一小时，平均偏差不到 0.6%
多步预测（t+1~t+3）1.146%越往后越不准，误差翻倍

反归一化后的样例对比（预测 vs 实际）：3008.74 / 3023.00、2955.53 / 2935.00、2900.17 / 2899.00——确实贴得很紧。

五、SVR：为什么还需要一个非线性模型

05
ARIMA 是线性统计方法；当序列里的非线性它映射不了时，就轮到 SVR——靠核函数升维来抓非线性。
SVM

特征空间里的一个超平面：分类时当边界，回归时当最佳拟合线。靠核函数把数据映射到更高维空间，使其更容易分开。

SVR

SVM 用于回归的变体：找一条容纳最多数据点的最佳拟合线（在高维里是超平面）。

为什么用它

教材原话：很多时间序列数据有非线性，线性模型映射不了；SVM 在回归任务中考虑非线性的能力，使 SVR 在预测上取得成功。

5.1 关键改造：把序列reshape 成 [batch, timesteps]

SVR 不是序列模型，得先把数据改造成「用前 N 步预测第 N+1 步」的监督学习格式。教材取 timesteps = 5：输入前 4 步，输出第 5 步。

python 
timesteps = 5

train_data_timesteps = np.array([[j for j in train_data[i:i+timesteps]]
                                 for i in range(0, len(train_data)-timesteps+1)])[:,:,0]
# (1412, 5)

x_train, y_train = train_data_timesteps[:, :timesteps-1], train_data_timesteps[:, [timesteps-1]]
x_test,  y_test  = test_data_timesteps[:,  :timesteps-1], test_data_timesteps[:,  [timesteps-1]]

# x_train (1412, 4)   y_train (1412, 1)
# x_test  (44, 4)     y_test  (44, 1)
注意样本数变少了：1416 → 1412、48 → 44。因为滑动窗口切不出完整的头尾。这种「用滞后值当特征」的构造法是所有非序列模型做时间序列的通用套路。

5.2 建模与三个 MAPE

python 
model = SVR(kernel='rbf', gamma=0.5, C=10, epsilon=0.05)
model.fit(x_train, y_train[:, 0])

六、ARIMA vs SVR

维度ARIMA / SARIMASVR
出身统计学的线性方法ML 的核方法
强项趋势、季节性、自相关结构非线性关系
要调的东西p,d,q + P,D,Q，主观且耗时kernel、gamma、C、epsilon、timesteps
评估方式walk-forward，每步重训（贵）一次 fit，直接 predict（快）
本例最佳成绩单步 0.557%（更准）测试 1.262%
可解释性参数有统计含义，能出 summary 表黑盒，靠超参搜索
别急着宣布 ARIMA 赢了。 两者并不可比：ARIMA 报的是「单步 t+1」的 0.557%，SVR 报的是「测试集整体」的 1.262%，口径不同。真要公平对比，得让 SVR 也做 t+1、ARIMA 也报同一段的多步结果。

七、读完发现的问题与提醒

1 测试集只有 48 小时（2 天）

本期最值得警惕的一点。test_start_dt 是 2014-12-30，数据到 2014-12-31 结束，测试集就 48 行；SVR 再经滑动窗口一削只剩 44 个样本。在 44 个样本上比较「1.262% vs 0.557%」意义有限。SVR 在 26300 个样本的全量数据上得到的 2.057%，反而是更可信的泛化数字。

2 教材正文与代码的日期对不上

第 2 讲正文写「把 9 月 1 日到 10 月 31 日这两个月划给训练集，11 月 1 日到 12 月 31 日给测试集」，但代码里是 2014-11-01 到 2014-12-30。第 3 讲照抄时把这个错误一起继承了。以代码为准。

3 order 中途从 (4,1,0) 悄悄变成 (2,1,0)

初次建模用 order=(4,1,0)，进入 walk-forward 时换成了 (2,1,0)，教材没有解释。合理的推测是为了控制重训成本（48 次 × SARIMAX），但也可能是笔误——自己复现时值得两个都跑一遍对比。

4 季节周期 24 是硬编码的先验

seasonal_order=(1,1,0,24) 里的 24 来自「小时数据的日周期」。这个数字必须你自己判断：换成日数据就是 7（周）或 365（年），搞错了模型就学歪。

5 MAPE 有个天生的坑：实际值接近 0 时会爆掉

MAPE 的分母是 actual。教材只给了定义没提这事。遇到负荷接近零的时刻，MAPE 会异常放大。实践里常备 MAE / RMSE / sMAPE 一起看。

6 SVR 那课的「全量评估」才是真考验

把 2012–2014 全部 26300 个样本跑一遍得 2.057%，比测试集的 1.262% 高不少。这才是模型在真实分布上的表现——只报测试集数字会美化结果。

7 这套流程默认「规律会延续」

ARIMA 和 SVR 都是从历史推未来。教材列的「Abrupt changes 突变」（疫情导致企业骤停）正是这类模型的死穴——断点之后的历史不再有效。这也是第 1 讲要把「突变」单列为一种特征的原因。

结语

  1. 时间序列的第一铁律：测试集必须晚于训练集。 随机切分会让模型偷看未来，所有指标作废。这是它跟前面所有模块最根本的区别。
  2. 行的顺序就是信息。 所以不能 shuffle、不能用普通的 K 折交叉验证；要用前进验证（walk-forward）——教材称为时间序列评估的黄金标准。
  3. 先识别六个特征，再谈建模。 趋势、季节性、异常值、长周期、恒定方差、突变——把它们当噪声削弱，模型才有东西可学。识别的手段就是画图，包括放大画。
  4. 非平稳先差分。 平稳性 = 分布不随时间平移而变；差分 = 去掉非常数趋势、稳定均值。这是 ARIMA 里那个 I。
  5. ARIMA 是线性的，非线性的部分交给核方法。 这正是教材要在同一份数据上再跑一遍 SVR 的理由——不是为了比高低，而是展示线性 vs 非线性两条路线。
  6. 非序列模型做时间序列，靠「滞后值当特征」。 把序列 reshape 成 [batch, timesteps]，用前 N 步预测第 N+1 步；代价是样本数减少 timesteps-1 个。
  7. 看指标先看样本量。 本例测试集只有 48 小时、SVR 更是只剩 44 个样本，而全量 26300 个样本的 MAPE 是 2.057%。在几十个样本上争 0.5 个百分点的胜负，不如扩大评估范围。
  8. MAPE 好读但有盲区。 「10 就是平均偏 10%」很直观，但分母是实际值，接近零时会失真，备一个 MAE/RMSE 更稳妥。
