回归回答「是多少」，分类回答「是哪一类」。这一模块四讲跑完，我对「模型上线」这件事的完整链路第一次有了实感：清洗 → 平衡 → 训练 → 评估 → 转成 ONNX 塞进浏览器。

上一个模块我们用同一个南瓜数据集把回归讲完了。这一模块换了个更香的数据集：2448 道亚洲与印度菜，384 个 0/1 配料列，任务是「给我一堆食材，猜它是哪国菜」。四讲下来我最深的感受是——决定成败的不是算法，而是数据平不平衡、以及你有没有看对指标。

一、分类到底在做什么：从「是多少」到「是哪个」

01
分类是有监督学习，和回归是同一套路数：给带标签的数据，学一个从输入到输出的映射，只不过输出从连续值变成了离散的类别。
二分类 Binary

只有两个候选类。例：这封邮件是不是垃圾邮件？这个南瓜是不是白色？

多分类 Multiclass

三个及以上候选类，且每个样本只属于一个。本文的「泰 / 日 / 中 / 印 / 韩」五选一就是典型。

多标签 Multilabel

一个样本可以同时属于多个类（一道菜既是「辣」又是「素食」）。这一模块没涉及，别和多分类搞混。

数据长这样：每一行是一道菜，每一列是一种配料，1 表示用了、0 表示没用。

python 
import pandas as pd

二、第一讲：清洗与平衡，比调参重要得多

2.1 先看看每个菜系爱用什么

课程给了一个很巧妙的小函数：把 DataFrame 转置、按列求和、再去零排序，就得到了「这个国家最常出现的配料」。

python 
def create_ingredient_df(df):
    ingredient_df = df.T.drop(['cuisine','Unnamed: 0']).sum(axis=1).to_frame('value')
    ingredient_df = ingredient_df[(ingredient_df.T != 0).any()]
    ingredient_df = ingredient_df.sort_values(by='value', ascending=False, inplace=False)
    return ingredient_df

thai_ingredient_df = create_ingredient_df(df[df.cuisine == "thai"])
thai_ingredient_df.head(10).plot.barh()

五个国家画完五张图，结论很直观：rice、garlic、ginger 在五个菜系里都是顶流。这种「人人都有的特征」对区分任务毫无帮助，只提供噪声，所以直接删掉：

python 
feature_df = df.drop(['cuisine', 'Unnamed: 0', 'rice', 'garlic', 'ginger'], axis=1)
labels_df  = df.cuisine
这一步的思路值得记住：不是「特征越多越好」，而是要删掉那些在所有类别里分布都一样的特征。它们的方差贡献为零，白白增加维度。

2.2 SMOTE：用插值造出少数类样本

SMOTE（Synthetic Minority Over-sampling Technique）不是简单复制少数类样本，而是在少数类样本之间做插值生成新样本。一句 fit_resample 就能把五类全拉到 799：

python 
from imblearn.over_sampling import SMOTE

oversample = SMOTE()
transformed_feature_df, transformed_label_df = oversample.fit_resample(feature_df, labels_df)

print(transformed_label_df.value_counts())
# korean 799 | chinese 799 | indian 799 | japanese 799 | thai 799

transformed_df = pd.concat([transformed_label_df, transformed_feature_df], axis=1, join='outer')
transformed_df.to_csv("../data/cleaned_cuisines.csv")   # 后面三讲都用它
原始数据2448 行，五类不均
→
删共通配料rice / garlic / ginger
→
SMOTE 插值少数类合成新样本
→
均衡数据5 × 799 = 3995 行

这一步做完，后面三讲的输入数据就固定了

我自己加的一个警告（教材没提）：课程是先 SMOTE 再 train_test_split，这会让合成样本混进测试集，指标偏乐观。严谨做法是先切分、只对训练集做 SMOTE，或者干脆用 imblearn.pipeline.Pipeline 把采样器包进去，配合交叉验证才不会泄漏。

三、第二讲：逻辑回归做多分类，三个必须看懂的输出

02
逻辑回归天生是二分类器，要处理五分类得靠 one-vs-rest 或 multinomial 两种策略；这一讲还第一次出现了「给单个样本做解释」的操作。

3.1 教材写法与新版本 sklearn 的冲突

python 
X_train, X_test, y_train, y_test = train_test_split(
    cuisines_feature_df, cuisines_label_df, test_size=0.3)

lr = LogisticRegression(multi_class='ovr', solver='liblinear')
model = lr.fit(X_train, np.ravel(y_train))
print("Accuracy is {}".format(model.score(X_test, y_test)))   # 0.80+

这里有两个参数需要理解：

参数取值含义
multi_class'ovr'one-vs-rest：为每一类训练一个「是不是这一类」的二分类器，共 5 个
multi_class'multinomial'直接优化交叉熵（softmax），只被 lbfgs / sag / saga / newton-cg 支持
solver'liblinear'优化算法；它不支持三分类以上，所以必须配 ovr
我实际踩到的坑：我的环境是 sklearn 1.9.0，multi_class 参数已经被移除，上面那行会直接报 TypeError: LogisticRegression.__init__() got an unexpected keyword argument 'multi_class'。新版把多分类统一成 multinomial 实现，OvR 改由 OneVsRestClassifier 提供：

from sklearn.multiclass import OneVsRestClassifier
model = OneVsRestClassifier(LogisticRegression(solver='liblinear')).fit(X_train, np.ravel(y_train))

或者直接 LogisticRegression(max_iter=1000) 用默认的 lbfgs + multinomial。我在三分类模拟数据上对比过：OvR 0.813 vs 默认 0.827，差别不大。

3.2 输出一：单个样本的「人话解释」

python 
print(f'ingredients: {X_test.iloc[50][X_test.iloc[50]!=0].keys()}')
print(f'cuisine: {y_test.iloc[50]}')
# ingredients: Index(['cilantro', 'onion', 'pea', 'potato', 'tomato', 'vegetable_oil'], ...)
# cuisine: indian

这行是我这一讲最喜欢的一句，拆开看：iloc[50] 取第 51 行 → != 0 得到布尔掩码 → 布尔索引筛出用过的配料 → .keys() 拿到配料名（Series 上等价于 .index）。用 != 0 而不是 == 1 是通用写法，遇到计数或 TF-IDF 权重也一样成立。

四、第三讲：照着 cheat sheet 试五把刀

03
选算法不是抓阄。Scikit-learn 有一张「机器学习地图」：>50 样本、要预测类别、有标签、<10 万样本 → 先试 Linear SVC → 再 KNN → 再 SVC 与集成方法。

课程的做法是把分类器塞进一个字典，循环训练、统一打印报告，非常值得照抄：

python 
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import SVC
from sklearn.ensemble import RandomForestClassifier, AdaBoostClassifier

C = 10
classifiers = {
    'Linear SVC': SVC(kernel='linear', C=C, probability=True, random_state=0),
    'KNN classifier': KNeighborsClassifier(C),
    'SVC': SVC(),
    'RFST': RandomForestClassifier(n_estimators=100),
    'ADA': AdaBoostClassifier(n_estimators=100)
}

for name, classifier in classifiers.items():
    classifier.fit(X_train, np.ravel(y_train))
    y_pred = classifier.predict(X_test)
    print("Accuracy for %s: %0.1f%%" % (name, accuracy_score(y_test, y_pred) * 100))
    print(classification_report(y_test, y_pred))

4.1 五把刀的实测对比

分类器准确率一句话原理表现
Linear SVC78.6%找一条（超）平面把类别分开，间隔最大基线合格
KNN（k=10）73.8%看最近的 k 个邻居投票高维稀疏 0/1 数据上距离失效
SVC（RBF 核）83.2%把样本映射到高维再分割，能画非线性边界明显变好
Random Forest84.5%100 棵随机决策树投票，靠随机性抑制过拟合本场最佳
AdaBoost72.4%串行训练弱分类器，每轮专注分错的样本最差，对本数据不适合
KNN为什么垫底

380 维的 0/1 稀疏向量，「距离」这个概念本身变得很不可靠，两条菜谱几乎总是「同样远近」。

RF为什么最好

树模型天然擅长「if 有鱼露 and 有柠檬草 → 泰餐」这类特征组合判断，而配料表正是这种结构。

ADAAdaBoost 为何拉胯

默认基学习器是深度 1 的决策树（决策树桩），对这种需要多特征组合的任务表达能力不够。

读代码时的一个发现：教材里写 KNeighborsClassifier(C)，而 C = 10 本来是给 SVC 用的正则化参数。KNN 的第一个位置参数其实是 n_neighbors，所以这里等价于是「取 10 个邻居」——数值上的巧合，不是参数意义上的复用。抄代码时别把两个同名变量当成一回事。

五、第四讲：把模型塞进浏览器

04
这一讲把「模型」从 notebook 里拿了出来：训练 SVC → 转成 ONNX → 用 onnxruntime-web 在纯前端推理，全程离线可跑。
训练 SVCkernel='linear', C=10
→
skl2onnx 转换声明输入 [None, 380]
→
model.onnx用 Netron 可视化检查
→
index.html 推理勾选配料 → 猜菜系

和上一个模块的 Flask + pickle 方案相比，这条路不需要后端 Python 进程

5.1 导出 ONNX

python 
from skl2onnx import convert_sklearn
from skl2onnx.common.data_types import FloatTensorType

initial_type = [('float_input', FloatTensorType([None, 380]))]   # 380 = 配料特征数
options = {id(model): {'nocl': True, 'zipmap': False}}           # 去掉冗余输出，缩小体积

onx = convert_sklearn(model, initial_types=initial_type, options=options)
with open("./model.onnx", "wb") as f:
    f.write(onx.SerializeToString())

两个 option 都是实用技巧：zipmap=False 去掉分类模型默认附加的「字典列表」输出；nocl=True 不把类别信息写进模型，能显著减小文件体积。

5.2 前端推理

html 
<script src="https://cdn.jsdelivr.net/npm/onnxruntime-web@1.9.0/dist/ort.min.js"></script>
<script>
    const ingredients = Array(380).fill(0);          // 380 维输入向量
    const checks = [...document.querySelectorAll('.checkbox')];

    checks.forEach(check => {
        check.addEventListener('change', function() {
            ingredients[check.value] = check.checked ? 1 : 0;   // value = 配料在表中的列索引
        });
    });

    async function startInference() {
        const session = await ort.InferenceSession.create('./model.onnx');
        const input  = new ort.Tensor(new Float32Array(ingredients), [1, 380]);
        const results = await session.run({ float_input: input });
        alert('You can enjoy ' + results.label.data[0] + ' cuisine today!');
    }
</script>

三个关键点：① 每个 checkbox 的 value 是配料在数据集里的列索引（课程提供了 ingredient_indexes.csv 对照表）；② 输入必须构造成 [1, 380] 的 Float32Array；③ float_input 这个 feed 名字必须和导出时声明的一致，可以用 Netron 打开模型确认。

六、我实际踩到的坑

坑 1 multi_class 参数已消失

sklearn 1.9 已移除该参数，教材代码直接 TypeError。多分类要用 OneVsRestClassifier 包一层，或改用默认 solver；另外 liblinear 本身不支持 ≥3 类，这就是当年必须配 ovr 的原因。

坑 2 SMOTE 在切分之前做 = 数据泄漏

教材先做 SMOTE 再 train_test_split，合成样本会混进测试集，指标偏乐观。严谨顺序：先切分 → 只对训练集采样；或用 imblearn.pipeline.Pipeline。

坑 3 y 是 DataFrame 不是 Series

课程里 cuisines_label_df 来自 df[['cuisine']]（双括号），所以训练要写 np.ravel(y_train)；查看标签时 y_test.iloc[50] 返回的是一整行 Series，得写 y_test.iloc[50, 0] 或 .item() 才拿到字符串。

坑 4 教材把测试集准确率打印成 "Accuracy (train)"

第三讲的循环里标签写的是 train，实际算的是 accuracy_score(y_test, y_pred)。读指标前先看清它到底用的哪一份数据，别被变量名带偏。

结语

  1. 先平衡，再建模。 category 数量差 2~3 倍就足以毁掉少数类的学习效果；SMOTE 用一行 fit_resample 解决，但记得只对训练集做。
  2. 别只盯 accuracy。 本模块里整体 80% 背后，印度菜 0.92、中国菜 0.72——多分类一定要看 per-class 的 precision / recall / F1 和 macro 平均。
  3. 选算法要「按图索骥 + 横向对比」。 照着 sklearn 的 cheat sheet 走，再用字典循环一次性跑完五个分类器对比，比凭感觉挑高效得多。
  4. 树模型赢在特征组合。 配料这种「有没有」的稀疏 0/1 特征，随机森林比 KNN、线性模型更合适；KNN 在高维稀疏数据上基本失效。
  5. 模型要能被用起来。 ONNX + onnxruntime-web 让我第一次体会到「训练在 Python、推理在浏览器」这条链路，也让模型真正脱离了 notebook。
