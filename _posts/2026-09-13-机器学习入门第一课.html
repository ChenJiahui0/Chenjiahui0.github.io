读书笔记 · 微软 ML for Beginners 第一模块（Introduction）四讲归纳 人工智能 机器学习 AI 历史 负责任的 AI 工程流程
一句话掌握全篇
机器学习 = 数据 + 算法 → 可复用的「模式」

决定模型上限的是数据质量，决定模型下限的是是否负责任；而入门第一步，是把概念坐标立起来。

你早上被手机的天气提醒叫醒，通勤路上刷到的推荐内容、外卖平台给你的满减券、银行秒批的信用卡——这些背后大概率都有机器学习在跑。但真让人说清「机器学习到底是个什么东西」，多数人会卡住。第一讲开门见山点出了这个尴尬：machine learning 是当下最热门的词之一，但它的机制对大多数人来说是黑箱。所以入门的第一件事不是写代码，而是把概念坐标立起来。

一、先立坐标：AI、ML、DL、DS 是什么关系

数据科学 Data Science

最大的范畴，一条从数据采集到价值交付的完整链路，ML 是其中一环。

人工智能 AI

让机器表现出「智能行为」的总目标：感知 → 处理 → 决策 → 行动。

机器学习 ML

AI 的重要子集：用专门的算法，从感知到的数据中挖出有意义的信息与隐藏模式，支撑理性决策。

深度学习 DL

用多层神经网络来做 ML，是 ML 的一个分支，本课不涉及。

⊃
包含关系：AI 最大 → ML 是 AI 的子集 → DL 是 ML 的一支；DS 是与之并列的更大范畴。

为什么 ML 的动机像「人脑」

课程给了一条很好懂的类比链——把一个孩子学习世界的过程，原样搬到机器上：

感知接收外界信息
→
处理逐渐学到隐藏规律
→
决策形成逻辑规则
→
行动 = 智能行为搬进机器即为 AI

人脑这种持续学习与自我升级的能力，叫作「脑可塑性（brain plasticity）」

两个必须记住的边界：① 本课明确不覆盖深度学习、神经网络与 AI，只讲「经典机器学习」，主力工具是 Scikit-learn；② 脏数据、噪声数据会让再先进的算法也预测不准——数据质量往往比算法更决定上限。

二、再认来路：一部「浪潮与寒冬」交替的历史

一开始我以为历史只是背年份，读下来发现它其实在讲一个规律：AI 的每次起落，几乎都由「算力 × 数据 × 提问方式」这三件事决定。

那些「史前」的数学与算法基石

年份事件为什么重要
1763 / 1812贝叶斯定理用先验知识推算事件概率，是一切「推断」的根基。
1805最小二乘（Legendre）解决数据拟合问题，是后面回归单元的主角。
1913马尔可夫链（Markov）用上一状态描述下一状态，序列建模的起点。
1957感知机（Rosenblatt）线性分类器，深度学习的祖先。
1967最近邻原本用于地图寻路，在 ML 中用于发现模式。
1970反向传播训练前馈神经网络的关键算法。
1982循环神经网络 RNN从 FFN 衍生，可构建时序图，序列任务的起点。
AI / ML 作为独立领域要到 1950 年代才成型，但关键算法、统计与数学发现要早得多，且与这个时代相互重叠——历史不是从「AI」这个词才开始的。

浪潮与寒冬：三次起落

1950图灵：会思考的机器

关键词：机器能否思考

提出图灵测试，为「能思考的机器」这一概念打下地基。

1956达特茅斯夏季研究项目

关键词：「人工智能」一词诞生

John McCarthy 牵头、Marvin Minsky 参与；提出「学习的每个方面，原则上都可被精确描述，从而使机器能模拟它」。

1956–1974黄金年代

关键词：乐观与政府资助

NLP 研究繁荣，出现 Shakey 机器人、聊天机器人 Eliza、积木世界 SHRDLU 等「微世界（micro-worlds）」原型。

1974–1980第一次 AI 寒冬

关键词：承诺落空，资金枯竭

算力不足 + 组合爆炸 + 数据稀缺 + 提问方式被质疑（中文屋理论、Eliza 的伦理争议）。

1980s专家系统

关键词：规则引擎 + 推理引擎

第一批真正成功的 AI 软件形态，是「规则引擎定义业务需求 + 推理引擎推导新事实」的混合系统。

1987–1993AI Chill

关键词：专用硬件被 PC 冲垮

专用硬件过度专用，个人电脑崛起并与之竞争，计算民主化反而为后来大数据铺路。

1993–2011数据与算力起飞

关键词：数据爆炸，学科成熟

2007 年智能手机是关键节点，数据量与算力指数增长，算法同步演进，AI 从「野蛮生长」走向真正学科。

Now无处不在

关键词：风险、隐私与监管

AI 触及生活每个角落，重心转向理解算法对个人与社会的风险与影响。

寒冬的四个原因 + 一个学派之争

1算力限制

可用的计算能力远远不够。

2组合爆炸

需求越多、参数指数增长，而算力没有同步进化。

3数据稀缺

缺乏数据，无法测试、开发与迭代算法。

4提问方式被质疑

中文屋理论否定「真理解」；Eliza 这类系统进入社会的伦理性受挑战。

Scruffy 邋遢派

靠着把程序反复调到出结果为止，代表系统有 ELIZA、SHRDLU。

Neat 整洁派

强调逻辑与形式化问题求解。1980 年代因「可复现、可解释」的需求逐渐占上风。

三、最容易被跳过、却最重要的一讲：公平与负责任 AI

如果只让我推荐这一模块的一讲，我会选第三讲。它的起点非常朴素：AI 已经在做医疗诊断、贷款审批、欺诈检测这类日常决策了，所以模型工作得好不好直接关系到人。而现实是——AI 系统会达不到预期，也会有不良后果，因此我们必须能理解和解释它的行为。

五种「不公平」的伤害

类型含义典型例子
分配 Allocation系统性偏袒某个群体某性别或族裔在贷款审批中被优待
服务质量 Quality of service只针对单一场景训练，而现实更复杂皂液器识别不了深色皮肤
贬低 Denigration不公正地给事物或人贴标签图像模型把深色人种照片误标为「大猩猩」
过度 / 不足代表 Representation某群体长期缺席某职业，而服务持续强化它职业画像固化
刻板印象 Stereotyping给群体预设属性英⇄土翻译因性别联想而产生偏差
速记口诀：分 · 服 · 贬 · 代 · 刻 —— 分配、服务、贬低、代表、刻板。

负责任 AI 的六原则

①公平 Fairness

相似的情况给出相似结论；警惕无意中被引入数据的偏见。

②可靠与安全

不只看「跑得通」，重点覆盖离群场景：夜间、暴雨、暴雪、突然冲出的孩子与宠物、施工路段。

③包容 Inclusiveness

设计上让每个人都能用。全球约 10 亿残障人士，消除障碍就是创造机会。

④隐私与安全

尊重隐私、抵抗攻击；数据来源与完整性要可追溯（如 GDPR）；直面「个性化」与「隐私」的张力。

⑤透明 Transparency

要玻璃盒，不要黑盒。很多问题只有在「能解释」时才暴露得出来。

⑥问责 Accountability

设计者与部署者要对系统负责。人脸识别等敏感技术尤其如此，须防大规模监控。

速记口诀：公 · 可 · 包 · 隐 · 透 · 责 —— 公平、可靠、包容、隐私、透明、问责。

两个落地抓手

① 影响评估（Impact Assessment）：在训练模型之前先做一次「风险体检」。

  1. 对个人的不利影响：是否有未支持的用法、已知限制被误用，从而可能伤害个体。
  2. 数据要求：数据从哪来、量是否足够、是否合规（GDPR / HIPAA）。
  3. 影响汇总：列出潜在伤害清单，并在整个 ML 生命周期持续跟踪是否已被缓解。
  4. 目标达成度：逐条对照六大原则自检，找出缺口。

它的本质，就是先回答三个问题：系统用来做什么？部署在哪里？谁会与它交互？

② 用负责任 AI 来调试：传统指标只是量化聚合，回答不了「有没有违反原则」；而模型本身又是黑盒。Responsible AI Dashboard 提供四种能力来补这个缺口。

✕错误分析

找出模型的错误分布，判断它如何影响公平与可靠。

◎模型概览

发现不同数据队列（cohort）之间的性能差异。

▤数据分析

理解数据分布，识别可能引发公平 / 包容 / 可靠问题的偏见。

?模型可解释性

搞清什么影响了预测，为透明与问责提供依据。

读完这一讲最深的感受是：机器学习从来不是纯技术问题，而是一个「社会技术（sociotechnical）」问题。这句话值得贴在显示器上。预防伤害的三条行动：团队背景多样化、投入反映社会多样性的数据集、在 ML 全生命周期发展检测与纠错方法。

四、回到工程：一个模型是怎样「炼」出来的

第四讲把流程讲得非常干净，一共七步：

1提出一个问题

能靠 if-else 写死的不必用 ML。ML 真正擅长的是「基于大量数据做预测」。

2收集 + 准备数据

注意来源、固有偏见，记录数据出处；再做合并、归一化、字符串转数值、清洗、打乱。

3选择训练方法

依据问题与数据性质挑选，这一步最需要经验，也最需要试错。

4训练模型

本质是 model.fit(X, y)：让模型对发现的模式做假设、验证、接受或拒绝。

5评估模型

用模型从未见过的测试数据衡量性能，打印指标表。

6超参数调优

根据表现调整控制算法行为的「旋钮」，重新训练。

7预测 / 推理

用全新数据测试准确度；生产中常是「用户按按钮 → 变量送进模型 → 推理」。

速记口诀：问 → 数 → 选 → 训 → 评 → 调 → 预。评估不理想时，回到第 3 步「换方法 / 调参数」重新来过——这是个循环，不是直线。

特征与目标：最基础也最容易混

概念符号含义例子
特征 FeatureX可度量的属性，也就是输入变量。date / size / color
目标 Targety要预测的结果，也叫标签（label）。12 月哪种颜色的南瓜最便宜；旧金山哪个社区房价最高
特征提取 Feature Extraction

用原特征的函数造出新特征。

特征选择 Feature Selection

只返回原特征的子集，不创造新特征。

数据集为什么要三分

子集作用备注
训练集 Training用来拟合模型。占原数据的大部分。
测试集 Testing独立数据，用来确认模型性能。模型此前从未见过。
验证集 Validating更小的独立组，用来调超参数或架构。数据量小或问题简单时可以没有。

拟合的三种状态

欠欠拟合 Underfitting

学得太少：训练数据和没见过的数据都分析不准。

好拟合良好

面对不熟悉的数据仍能保持准确——模型拟合度衡量的正是这一点。

过过拟合 Overfitting

学得太死：把细节和噪声也学进去了，训练集表现极好但泛化差。

用一句话记住「模型拟合度」：它是模型面对不熟悉的数据时，内部函数的准确程度。

五、给同样入门的三条建议

  1. 先把概念坐标立住再写代码。分不清 AI / ML / DL、特征 / 目标，后面只会越学越乱。
  2. 把「负责任 AI」当必修而不是选修。五类伤害 + 六原则，是这门课里最「长期有用」的知识。
  3. 流程比算法先学。七步流水线会陪你走完整个职业生涯，而具体用哪个算法，随时可能被淘汰。

结语

课程结尾有一句话我很喜欢：机器学习通过从真实或生成的数据中发现有意义的洞见，把「模式发现」这件事自动化了；它已经在商业、健康、金融等领域证明了自己的价值。而在不远的将来，理解机器学习的基础，会因为它的普及而成为任何领域的人的必修课。

作为「第一代把 AI 带入社会的人」，我们这一代最核心的问题或许不是「能不能做出来」，而是：如何让机器对人负责，以及如何让造机器的人对所有人负责。
